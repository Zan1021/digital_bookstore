**Author:** Naz

**Status:** Draft — awaiting execution
**Supersedes the open item in:** `specs/manifest-scene-graph-unification` (§5.3, the render
layer that was never fully closed for the vocabulary/phonics renderer)

---

## Introduction

The V8 engine's promise is **book-agnostic**: upload any book, any layout, and it
translates, re-typesets, and narrates correctly — or, where it cannot, it fails closed and
flags the page for human review rather than shipping something broken.

That promise holds today for cover, copyright, story, and back-cover pages across
different books. It does **not** yet hold for **vocabulary / word-table / phonics** pages
on any book other than the original calibration book ("A Fun Place").

Two defects, both proven on a live end-to-end run of a *new, previously-untested* book
("Kolulu S2 BK3 — My Senses"):

1. **Font-size-dependent classification (FIXED this session, kept here for the record
   and regression coverage).** The vocabulary detector used `small_font_count > 30`,
   which is a property of one book. "My Senses" sets its word table in 23pt, so the page
   misclassified as `story`. A structural (font-size-independent) detector was added.

2. **Source-text placement bridge (THE CORE DEFECT this spec fixes).** The vocabulary
   renderer (`render_vocabulary_page_v8`) builds its OWN manifest with a DIFFERENT id
   scheme (`p19-w-c1-001`) than the translation contract (`p19_s0006`), so it cannot map
   translations by id. It bridges by **normalized English source text**
   (`_contract_source_to_translation`). That bridge assumes the translation is a
   word-for-word match of the English source. It breaks whenever:
     - the content is **context-adapted** (phonics regenerated by OpenAI under the
       `educational_adaptation` policy — e.g. English `ck → rock, lock` becomes an
       Afrikaans phonics equivalent, not a literal translation), or
     - wording/segmentation differs from the source for any reason.
   When the bridge matches nothing, the engine reports `CONTRACT_BRIDGE_MISS`, fails
   closed, and the original **English** spans remain on the page.

The scene graph (`document_model.build_document_scene`) already produces, for these
pages, a correct structure with **stable ids** (`p19_s0006`), `cell_box`, alignment,
column indices, and merged-header info — the SAME id scheme as the contract. The fix is
to render the vocabulary/phonics page **by stable id + geometry from the scene graph**,
eliminating the source-text bridge entirely.

Language codes: `en` (source), `af` (Afrikaans), `zu` (Zulu).

---

## Glossary

- **Scene graph** — `document_model.DocumentScene` / `PageScene` / `TextUnit`; the single
  source of truth for page structure, built from the PDF geometry. Book-agnostic.
- **Contract** — the `{id → translation}` mapping (with `source_text`, `page_number`,
  structure fields) sent from PHP to the engine in the translations JSON.
- **Source-text bridge** — the current mechanism that matches a manifest item to a
  translation by comparing normalized English source strings. The thing being removed.
- **Stable id** — a per-span identifier (`p{page}_s{index}`) shared by the scene graph,
  the contract, and `item_translations`.
- **educational_adaptation** — a `translation_policy` for phonics/sound-pattern units
  where the target text is REGENERATED (not translated 1:1); breaks source-text matching
  by design.

## Requirement 1 — Vocabulary/phonics pages render by stable id, not source text

**User story:** As the platform, I want to place each vocabulary/phonics unit's
translation onto its exact source span by stable id, so that any book's word tables
render correctly regardless of whether the translation matches the English wording.

#### Acceptance criteria
1. WHEN a vocabulary page is rendered AND a stable-id contract is available THEN the
   engine SHALL resolve each unit's translated text by its stable id
   (`id_to_translation[unit.id]`), NOT by matching source text.
2. WHEN placing a unit THEN the engine SHALL use that unit's scene-graph geometry
   (`bbox`, `cell_box`, `align_h`, `align_v`, `column_span`, `is_merged`) so headers,
   columns, and phonics cells land in their true cells.
3. The engine SHALL NOT depend on `_contract_source_to_translation` /
   `_manifest_source_to_translation` for placement when a stable-id contract is present.
4. The vocabulary renderer SHALL consume the SAME id scheme as the contract (the scene
   graph's `p{page}_s{index}`), so there is no id-scheme mismatch to bridge.
5. WHEN the scene graph classifies a page as vocabulary THEN the render path used SHALL be
   the id-based path (no per-book branching).

## Requirement 2 — Phonics / educational-adaptation units are placed correctly

**User story:** As a content owner, I want context-adapted phonics exercises to appear in
their cells in the target language, so that adapted content is not dropped or shown in
English.

#### Acceptance criteria
1. WHEN a unit has `translation_policy = educational_adaptation` THEN the engine SHALL
   place its regenerated target-language text by stable id exactly as for `translate`
   units.
2. `get_translatable_units()` (or the render's unit selection) SHALL include
   `educational_adaptation` units, not only `translate` units.
3. WHEN an adapted phonics unit has a translation in the contract THEN the rendered page
   SHALL show the adapted target text (no English fallback, no blank).

## Requirement 3 — Fail-closed preserved (no English leak, ever)

**User story:** As the platform, I want any unit we cannot confidently place to be blank +
flagged for review rather than rendered in English, so broken/English output never ships
silently.

#### Acceptance criteria
1. WHEN a vocabulary unit has NO translation for its id AND the page has translated
   content THEN the engine SHALL render that unit BLANK and add the unit/page to the
   review set (no fallback to English `source_text`).
2. WHEN any unit on a page is unresolved THEN the edition SHALL be set to
   `NEEDS_LAYOUT_REVIEW` (not publishable) and the qa_report SHALL record the unresolved
   ids.
3. The `allow_legacy_flat` opt-in path SHALL remain available but OFF by default.
4. The system SHALL NEVER render an English source string on a translated edition as a
   silent fallback.

## Requirement 4 — Book-agnostic, proven on multiple books

**User story:** As the founder, I want the fix validated on more than one book, so
"book-agnostic" is proven rather than asserted.

#### Acceptance criteria
1. The implementation SHALL contain no book-specific constants, page numbers, titles, or
   language-specific word lists in the render/classification path.
2. The fix SHALL be validated end-to-end on the new book ("My Senses"): its WOORDE page
   renders correct Afrikaans in the 3-column table.
3. The fix SHALL be validated on a SECOND, structurally different Kolulu title's
   vocabulary page.
4. WHERE a page type still cannot be rendered THE gate SHALL flag it for review (the
   safety net), and this SHALL be recorded as a known limitation, not a silent failure.

## Requirement 5 — No regressions

**User story:** As the team, I want the existing engine and app behaviour preserved, so
this fix does not break shipped functionality.

#### Acceptance criteria
1. All existing Python suites SHALL pass: `test_table_structure.py`, `test_render_gate.py`,
   `test_integration.py`, `test_unit.py`, `test_e2e_contract.py`, `test_second_book.py`,
   `test_manifest_flow.py`, `test_phonics_classification.py`.
2. The full Laravel test suite SHALL pass.
3. The original calibration book ("A Fun Place") vocabulary page SHALL still render
   correctly (no regression on the previously-working book).
4. Story, cover, copyright, and back-cover rendering SHALL be unchanged.

## Requirement 6 — Traceability & diagnostics

**User story:** As a maintainer, I want the render report to explain vocabulary placement
outcomes, so future failures are debuggable without re-deriving the pipeline.

#### Acceptance criteria
1. The render report SHALL record, per vocabulary page: units total, units placed by id,
   units unresolved (with ids), and the mapping mode used (`id` vs `legacy_flat`).
2. WHEN `CONTRACT_BRIDGE_MISS` can no longer occur on the id path THEN that flag SHALL
   only appear for explicitly legacy renders.
